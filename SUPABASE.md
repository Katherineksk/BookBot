# Shelf: подключение Supabase (шаг 2)

Как это устроено: приложение не обращается к базе напрямую. Каждый запрос идёт в серверную функцию `shelf-api`, она проверяет подпись Telegram (что запрос пришёл из твоего бота и от конкретного пользователя) и только потом читает или пишет данные этого пользователя. Прямой доступ к таблицам из браузера закрыт.

Пока функция не подключена, приложение работает как раньше и хранит данные на телефоне. При первом запуске с сервером книги и отметки с телефона переносятся в базу автоматически.

## Настройка (всё в браузере, ничего ставить не нужно)

1. **Проект.** На supabase.com → New project. Регион любой близкий (например, Frankfurt). Пароль базы сохрани у себя, мне он не нужен.
2. **Таблицы.** SQL Editor → New query → вставь содержимое файла `supabase/migrations/20261010000000_init.sql` → Run.
3. **Функция.** Edge Functions → Deploy a new function → Via Editor. Имя: `shelf-api`. Вставь содержимое `supabase/functions/shelf-api/index.ts` → Deploy. Затем в настройках функции выключи «Verify JWT» (Enforce JWT verification): функция сама проверяет подпись Telegram.
4. **Секреты.** Edge Functions → Secrets → добавь:
   - `TELEGRAM_BOT_TOKEN`: токен бота из @BotFather;
   - `ALLOWED_ORIGIN`: `https://katherineksk.github.io`.
5. **Адрес функции.** Он выглядит так: `https://<id-проекта>.supabase.co/functions/v1/shelf-api`. Его можно присылать в чат, это не секрет. Он вписывается в `index.html` в строку `const SHELF_API_URL = '';`.

Токен бота и ключи Supabase (service_role, secret) в чат не присылай.

## Что хранится
- `books`: книги (название, автор, статус, прогресс, цвет обложки, дата добавления) с id пользователя Telegram.
- `reading_logs`: отметки чтения по дням (страницы или минуты).
